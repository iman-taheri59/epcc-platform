## Fixes delivered

### 1. DEFECT-001: baseline/model-import row-level security

Forward migration: `app/database/migrations/2026_09_28_100000_fix_baseline_tenant_policies.php`.

Affected tables: `baseline_batches`, `engineering_items`, `baseline_discrepancies`, `model_imports`, `model_import_diffs`.

- Qualified participation checks now use `project_company`, not the absent `project_memberships.company_id`.
- Legitimate participating companies can read the shared engineering records.
- Removed/nonparticipating companies cannot retain access through stale user memberships or original creator provenance.
- A bound project scope applies to reads and writes; company portfolio reads without a project scope still work.
- SELECT, INSERT, UPDATE and DELETE policies are separate. Shared read permission does not grant deletion or modification of another company's records.
- Writes retain creator-company ownership and require an active project. Archive preserves reads but blocks inserts, updates and deletes.
- Changing a row's company to another company is refused.
- Empty/unset tenant settings fail closed without UUID cast errors.

`BaselineIsolationTest`: 14 tests, including mirrored read/write cases, HTTP/service refusals, archive behavior and ownership transfer. The initial archive fixture was corrected to call the actual archive service and assert the persisted state; mass assignment had silently ignored guarded Project lifecycle fields.

**Deployment status:** applied to disposable test databases only. No application database was reset or migrated. Back up and review the migration before deploying it with `php artisan migrate`. Rollback deliberately does not reinstall the known defective policies.

### 2. No more apparent success on denied writes

`BaselineService::accept()` and `resolve()` now explicitly reject non-creator-company edits. Import-diff acknowledgement rejects another company's record and refuses archived projects with an actionable validation response.

This aligns the application response with RLS; it does not introduce new cross-company approval powers. The intended role/capability matrix for future collaborative approvals remains separate product work.

### 3. Disabled existing sessions

`BindTenant` now checks `is_active` on every authenticated tenant-bound request. Previously a disabled identity injected as an existing session received HTTP 200 from a tenant route even though new login was blocked. The regression test now gets HTTP 403 before tenant binding.

The 71-test authentication/panel/identity/connection-reuse focused run passed after this change.

### 4. Public login privacy

The login page no longer queries or publishes the complete active-user directory by default, nor does it render the demo password autofill script.

- `EPCC_DEMO_LOGIN` defaults to false.
- Demo account selection requires explicit opt-in AND a local/testing environment.
- Production suppresses the chooser even if the opt-in flag was accidentally enabled.
- Demo queries are restricted to `.example` accounts.
- Demo email values passed to JavaScript use Blade's safe JS encoding rather than string interpolation.
- The login layout becomes a single column when the chooser is absent.

`LoginPrivacyTest` covers default privacy, explicit development opt-in and production refusal. The final 44-test login/authentication/preview rerun passed.

Enabling the chooser does not create accounts or reset passwords. Known demo credentials must never be deployed as real production accounts.

### 5. Test execution no longer deletes application documents

The previous `app/tests/bootstrap.php` recursively purged `storage/app/private/documents` before and after PHPUnit. It now creates a random, private temporary storage root per PHPUnit process and cleans only that root. Cleanup does not follow symlinks.

Config/route cache paths are isolated too. The base TestCase rejects non-PostgreSQL/non-test databases and superuser/BYPASSRLS roles before a fixture can run migrations. `BlobIntegrityTest` now creates its own fixture instead of depending on execution order.

A subprocess regression places a sentinel in the application document tree, links to it from test storage and verifies that the sentinel survives cleanup while test storage is removed. Another test proves a non-test database is rejected before destructive fixtures run.

### 6. Restore is non-destructive by default

`restore.sh` no longer runs `migrate:fresh` or seeds by default. The explicit reset path goes through `scripts/reset-demo.php`, requiring:

1. explicit `--reset-demo` and `--confirm-database=NAME`;
2. effective APP_ENV=local;
3. PostgreSQL;
4. an exact match with the effective configured database name.

`--check-only` validates these conditions without resetting data. The script now refuses to delete an existing real `app/vendor` directory, checks PostgreSQL readiness, restores locked JS dependencies at the project root and installs Composer through the distribution package manager rather than executing an unchecked downloaded installer.

This remains a **development sandbox bootstrap**, not a production installer. Installation branches were reviewed and syntax-checked; the complete restore/reset command was deliberately NOT executed during the audit. Reset guard checks were exercised in non-destructive mode.

### 7. Honest, portable test runners

- Missing `jsonschema` is now a validation failure, not a successful run with schema checks silently omitted.
- The aggregate runner fails preflight when required runtimes/dependencies/PDF tools are absent.
- PHPUnit skips/incomplete tests prevent the aggregate runner from reporting success.
- Browser harnesses resolve the project's `jsdom`, not `/home/user/node_modules`.
- `BrowserFixtureTest` renders fresh authenticated FA/EN document pages for JS harnesses; no stale `/tmp/sb.html` is required by the aggregate runner.
- `scripts/run-test-shards.py` runs test classes against distinct existing `epcc_test_*` databases and records assignments and JUnit output. It does not create/drop databases, but fixtures deliberately reset each supplied test database.
- Operational safety checks cover both reset guards and incomplete-run reporting.

### 8. Previous B16.9 repair retained

The fitting-dimension validation fixes and 13 regression tests remain green. No engineering dimensional values changed in this audit. The pack is still reference-data delivery; this audit did not build a new PHP consumer or expand to reducing/two-size fittings.
