# کنترل رشتهٔ شخصی در سه مسیر خواندن CDE

**۲۰۲۶-۱۰-۲۵ — پیاده و تست متأثر شد؛ مستقر نشده است.**

[English](CDE-READ-DISCIPLINE-EN.md) · [پیش‌بررسی شاهد](SCOPE-EVIDENCE-PREFLIGHT-FA.md) · [تشخیص بایت CDE](G01-CDE-EVIDENCE-INTEGRITY-FA.md)

## اصلاح، نه مجوز تازه یا تأیید شاهد

برش قبلی نشان داد DocumentController، doc.view پروژه را بدون رشتهٔ واقعی مدرک کنترل می‌کرد. RLS شرکت/پروژه به‌تنهایی discipline_scope شخص را اجرا نمی‌کند. این تغییر فقط شکاف **سه مسیر موجود فهرست، صفحهٔ بازبینی و دانلود GET/HEAD** را با معنای فعلی ABAC در AuthorizationPipeline می‌بندد؛ سیاست تجاری، نقش پیش‌فرض یا معرفی دسترسی تازه نیست.

کد اجراییِ تغییرکرده: `app/app/Http/Controllers/DocumentController.php`؛ تست جدید: `app/tests/Feature/CdeReadDisciplineTest.php`. migration، نوشتن policy/RLS/نقش/عضویت، تغییر route/view، کپی فایل، endpoint تازه یا impersonation مالک منبع نداریم. پیشنهاد/اظهارنامه/نظر، سرویس بایت/پیش‌بررسی، snapshot، خرید/انبار/رسید و پرچم‌های پذیرش/آمادگی ثابت‌اند؛ SA-01/02 و DA-01..04 دوباره پرسیده یا عوض نشده‌اند.

## رفتار دقیق مسیرها

- **فهرست `/projects/{projectCode}/documents`:** کاربر/طرح تازه و doc.view موجود، عضویت شخصیِ جاری و whitelist رشته در SQL، **پیش از خواندن مدرک و eager-load نسخه/فایل/کامنت/شرکت**.
- **بازبینی `/projects/{projectCode}/documents/{documentId}/review`:** پس از دروازهٔ پروژه/doc.view، فقط id و رشتهٔ واقعی از tenant/پروژهٔ اصلی با RLS خوانده می‌شود. رشته به ABAC داده می‌شود؛ پیش از نسخهٔ جاری، شرکت، کامنت/افراد و آمار.
- **دانلود `/projects/{projectCode}/documents/{documentId}/files/{fileId}`:** همان header حداقلی/رشتهٔ واقعی، سپس تطابق فایل/مدرک/پروژه؛ پیش از Storage::disk/exists/stream. UUID نامعتبر، tuple ناسازگار یا header غیرمجاز قبل از Storage رد می‌شود.

هر سه مسیر GET و HEAD را پوشش می‌دهند. `discipline_scope=null` همان دسترسی رشته‌ایِ نامحدود قبلی را **مشروط به تمام دروازه‌های دیگر/RLS** حفظ می‌کند؛ آرایه whitelist دقیق است و `[]` فهرست و شمارندهٔ صفر می‌دهد. scope خرابِ غیرnull/غیرآرایه نامحدود تلقی نمی‌شود. حروف/دپارتمان/نقش پیش‌فرض یا دامنهٔ تازه حدس زده نمی‌شود؛ queryهایی مثل discipline/as/discipline_scope هویت/دامنهٔ سرور را عوض نمی‌کنند.

شمارنده‌های state از همان مجموعهٔ پس از RLS و فیلتر شخصی محاسبه می‌شوند؛ مدرک مخفی عنوان/شماره/نام فایل، وابستگی یا شمارنده اضافه نمی‌کند. این فهرستِ قابل‌رؤیت است، نه inventory کامل پروژه. گزینه‌های ثابت رشته/type فرم و پرچم عمومیِ دکمه‌های create/issue قبلی باقی‌اند؛ مدرک اضافه نیستند و **گواهی اجازهٔ نوشتن در یک رشته نیستند**.

سه action خواندن، User واقعی را با id+company و company.plan تازه می‌خوانند؛ مدل/رابطهٔ cacheشدهٔ caller مجوز زنده نیست. نقش/عضویت از pipeline موجود کنترل می‌شود. درخواست بعدی محدودشدن scope یا غیرفعال‌شدن حساب را حتی با actor cacheشده می‌بیند. provisioning یا راه میان‌بر تازهٔ identity lookup ایجاد نشده است.

منبع نقطه‌ایِ مخفی/غایب/خارج‌رشته، پیش از جزئیات/Storage با404 مبهم رد می‌شود. رفتار قبلی احراز هویت، رؤیت پروژه/مشارکت/عضویت و رد اختیار عمومی/entitlement، از جمله403 یا redirect ورود، حفظ است. render انگلیسی/فارسی و رفتار inline/attachment/MIME/nosniff/CSP فایل مجاز ثابت‌اند؛ پیام اختصاصیِ جدیدی برای ترجمه نداریم.

WIP خصوصیِ شرکت دیگر همچنان با RLS مخفی است. انتشار عادی برای مشارکت‌کننده فقط وقتی قابل‌خواندن می‌ماند که خود شخص doc.view و رشتهٔ واقعی را هم داشته باشد؛ انتشار/مشارکت یا مالکیتِ مدرک شخصی scope را دور نمی‌زند. null-scope هم tenant خصوصی دیگری را باز نمی‌کند.

## مرز ادعا

- **پوشش سراسری CDE نیست.** بدنهٔ store/update/upload/deleteFile/comment/dispose و معنای اختیار آن‌ها بایت‌به‌بایت ثابت‌اند. رشتهٔ واقعی در مسیر نوشتن و پنل Filament/admin/خواندن جایگزین، ممیزی/اصلاح متمرکز جدا می‌خواهد؛ مجوز نوشتن بی‌صدا گسترش یا بازطراحی نشده است.
- گسترش RLS، SECURITY DEFINER، تغییر pipeline سراسری یا مجوز ارثی QA/خرید/خواندن منبع نداریم. معرفی فنی/منبع همچنان doc.view یا scope شخصی CDE نمی‌دهد.
- کنترل در زمان درخواست است؛ lease مجوز یا قطع stream شروع‌شده نیست. لغو دو worker هم‌زمان، حذف نسخهٔ قبلاً دانلودشده/cache، اتمیک DB/فایل‌سیستم یا مقاومت علیه مدیر مخرب تضمین نشده است.
- audit رد دسترسی، best-effort فعلی است و تراکنش درخواست ممکن است آن را rollback کند؛ تضمین audit دائمی تازه نداریم.
- دانلود عادیِ مجاز، گواهی هش/نگهداری/اعتبار جاری/رابطهٔ مهندسی نیست. پیش‌بررسیِ بدون تغییر فقط BYTES_CHECKED_UNRETAINED و بدون هویت دائمی/attachment است. ترکیب شاهد، پوشش تاریخی معتبر، تأیید مثبت/admission/چرخه/انتخاب مؤثر/دفتر کامل تعهدات و رزرو DA-03 همچنان بسته‌اند.

## اعتبارسنجی

- اولیه: **۱۲ تست جدید/۱۰۶ بررسی موفق،۲۳٫۳۵ ثانیه**؛ با متأثر هم‌پوشان است.
- نهایی متأثر: **۷۲ تست/۲۹۹ بررسی موفق،۱۵۱٫۰۳ ثانیه**؛ تست‌های HTTP جدید و DocumentFileTest، DocumentRegisterTest و ScopeEvidencePreflightTest.
- افزودهٔ متأثر: **ReviewCycleTest با۱۹ تست/۷۹ بررسی موفق،۳۶٫۷۱ ثانیه**؛ با۷۲تایی جداست. پس۹۱ تست هدفمندِ متمایز/۳۷۸ بررسی در دو اجرای نهایی موفق‌اند، **نه کل regression برنامه**. این اجراهای برنامه شکست/خطا نداشتند.

تست‌های جدید: SQL پیش از eager-load و شمارش فیلترشده؛ scope خالی/null؛ بازبینی/دانلود مجاز و header امن؛ رد جزئیات پیش از نسخه/کامنت؛ GET/HEAD خارج‌رشته بدون Storage؛ فایل/مدرک/پروژهٔ ناسازگار و UUID خراب؛ جعل query عامل/scope؛ actor cacheشده و محدودیت تازه/حساب غیرفعال؛ پنهان‌سازی فارسی/انگلیسی؛ WIP/انتشار شرکت دیگر با رشتهٔ شخص اصلی؛ و ثابت‌بودن سطرهای مدرک. Disk fake دادهٔ محلیِ scratch واقعی دارد؛ authorization موفق mock نشده است. HTTP/render برنامه تست شد، نه مرورگر یا capture HTML جدید.

Pint/lint دو PHP و whitespace موفق است. فرمان format اول پس از بازگردانی workspace، PHP نداشت؛ runtime/وابستگی/DB خصوصی socket-only بازسازی و سپس همهٔ format/testها موفق شدند. خطای ابزار در format.log حفظ شده و خطای تست برنامه نیست. نقش epcc بدون SUPERUSER/BYPASSRLS/CREATEDB، FORCE RLS و guardهای عدم تغییر ممیزی شدند. pipeline، فایل/register/review/preflight، route، view بازبینی و شش بدنهٔ نوشتن قبلی بایت‌به‌بایت کنترل شدند. view فهرست ویرایش نشد؛ هشِ ازقبل متفاوت آن با manifest قدیمی Oct18 حفظ/ثبت شد، نه reset یا بایت‌به‌بایت یکسان اعلام. تغییر رفتاری controller فقط سه action خواندن و دو helper خصوصی است؛ import/قالب‌بندی، از جمله constructor خالی با Pint، هم انجام شد. migration/داده/مجوز مشتری، CI/کل regression/مرورگر یا استقرار/commit/push نداریم؛ DB خصوصی بعد از بررسی متوقف شد.

شواهد: `docs/evidence/2026-10-25-cde-read-discipline/`. وضعیت راهنمای پیش‌بررسی/ledger/index دوزبانه اصلاح شد تا مشاهدهٔ نقص قبلی **فقط برای همین سه مسیر** تاریخی شود. بستهٔ افزایشی به تحویل قبلی preflight وابسته است؛ runtime/vendor/DB ندارد و بسته‌های قدیمی بازتولید نشدند.

## توصیهٔ بعدی

رشتهٔ واقعی در عمل‌های نوشتن CDE و پنل/مسیر جایگزین با قرارداد موجود entitlement/نقش/عضویت/RLS ممیزی شود؛ پرچم UI صرفاً راهنماست، نه اختیار. هم‌زمان دروازهٔ بستهٔ دائمی ثابت بماند: بدون رؤیت کامل وابستگی با عامل اصلی، بایت نگهداری‌شده، رابطهٔ purpose و اعتبار/ابطال جاری، بستهٔ کنترل‌شده نسازیم؛ operator/مدت نگهداری اختراع یا نظر قدیمی به بازبینی شاهد تبدیل نشود.
