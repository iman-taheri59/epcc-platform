## Accepted scope

User selected `next_scope_after_itp_context=tracking_register`: a **read-only project register**, filtering current visible prerequisites by status, declaring company and notice. This is not a new management/reporter role or an approval/readiness workflow. ADR-045's company-reader management / sender-current-issuer report / declaring-recipient confirm-or-reject / all-original-readers visibility remain. Exact inherited ITP context remains on prerequisite detail/history, not a new item catalog.

GET `/projects/{projectCode}/inspection-notifications/prerequisites`, route `inspection-notifications.prerequisites.index`, with normal authenticated web/project reader checks. Links appear on notification register, notice detail and prerequisite detail. The endpoint has no POST/write action, and responds with private/no-store/max-age0 caching. The page supports EN/FA/RTL without external assets or required JavaScript.

## Use and semantics

- Status: OPEN, REPORTED, FULFILLED, WITHDRAWN; empty means all. These are **prerequisite** statuses, not notice status. CANCELLED is not a prerequisite state and is invalid as this filter.
- Declaring company: stable UUID. Click **Filter this company** in a visible row to populate it, or enter its UUID. Filtering uses declaring `company_id`, not the sender/reporter/latest actor company. Names and codes are recorded snapshots; old/new names of the same UUID stay in one company filter. No project/global company directory, foreign people selector or hidden-company lookup is added.
- Notice number: bounded100-character literal case-insensitive substring. `%`, `_`, `!` and quotes are data, not SQL wildcards/code. This does not search item text, requirement body, report notes, old drafts or prerequisite history. **Filter this notice** copies the recorded notice number into this substring filter; it is not an exact-UUID filter and may match other numbers containing it.
- Filters intersect. Matching and all-currently-visible prerequisite counts are shown, never global/hidden totals. An unknown or currently hidden company/notice returns the same scoped zero, not a company existence oracle. Empty means no visible matching record, not absence of contractual prerequisites.

Rows show original notice number/link, declaring company recorded name/code/UUID, item reference/detail link, current prerequisite state/version and last action/person/company/server UTC. Requirement bodies and full history stay on the already authorized detail page. No source-document links or material/PO/MR/MTO authority is delegated. Names are snapshots, not live foreign directory joins.

Cancelled notices retain their prerequisite states and rows, with an explicit **cancelled original / retained read-only** label. An OPEN filter therefore can include an OPEN prerequisite on a cancelled notice; it is not a promise that the original work may proceed or that the requirement is actionable. Archived/nonwritable projects keep the register readable; all existing write prohibitions remain. The register does not manufacture withdrawals/fulfillment or alter receipt/issuance evidence.

## Pagination and validation

25 rows/page, `prerequisite_register_page`; current latest-action time descending and UUID ascending tie-break. Authorized visible counts/filter totals are server queries, not page lengths. Applying or clearing filters and row company/notice shortcuts resets pagination; language switch preserves filters/current page. Pagination links carry only normalized supported filters and language, not unrelated query/private context. High pages may be empty with a nonzero matching total. Normal Laravel page parsing is unchanged. This is a live offset-paginated view: follow-up activity may move records between page requests; no frozen export/snapshot consistency claim.

Optional query keys are `prerequisite_state`, `prerequisite_company`, `prerequisite_notice`. Trim ordinary surrounding whitespace; empty/null means no filter. Company UUID normalized to lowercase, valid note-search string `"0"` preserved. Arrays, malformed UUID/state, oversize text, invalid UTF-8 and NUL in supported text filters are refused. JSON422 includes validation errors; HTML422 is a localized error, not Referer redirect or silently unfiltered success. Unrelated query keys are ignored and not propagated.

The controller parses the original GET query before applying the allowlisted validator: global request trimming must not erase an all-NUL filter and convert it into an unfiltered request. Helper explicitly rejects NUL before Laravel's ordinary optional-string validation. SQL uses bound values and literal wildcard escaping. This is local to the new GET endpoint, not a global sanitizer/middleware change.

## Access and implementation

`InspectionNotificationService::prerequisiteRegister()` runs inside the same existing `read()` pipeline: fresh active identity/company, current project membership/participation/discipline, QAQC module and standards pack. No separate doc.view, issuer or drafter role is required **to read already visible prerequisites**, and none is granted. Sender sees its own issued notices; selected recipients see only their originally addressed notices. An unaddressed administrator sees no recipient records merely from configuration authority. A reader may see prerequisites declared by another selected company only on their shared original notice, as already approved.

The query joins prerequisite to original parent by notification/project/issued-version/discipline and requires ISSUED; both parent and prerequisite FORCE RLS still apply, with explicit project and current reader discipline. Visible-total count is computed before filters within that scope; filtered total and25-row page reuse it. Cancellation existence is a scoped subquery, not an alternate notice-access path. No source revisions/stages/private-draft history/prerequisite-event query or foreign directory fill. No new migration/table/index/RLS policy, role/grant, parent change, receipt/PDF/stock write, or technical approval/automatic work gate.
