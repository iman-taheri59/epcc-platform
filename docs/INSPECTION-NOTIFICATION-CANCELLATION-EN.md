## Explicit decisions — do not re-ask or broaden

After selecting `next_scope=issued_lifecycle`, the user selected:

1. **`lifecycle_authority=current_issue_grant`**: a currently explicitly nominated own-company issuer may cancel; not just the original issuer, drafter, settings administrator, recipient, or an inferred project role. Reusing this grant for cancellation is explicitly approved here, not implicit authority inferred from ADR-042.
2. **`lifecycle_transitions=cancel_only`**: independent cancellation only. No replacement draft, successor link, new issue number, rescheduling, undo, reissue, rollback to DRAFT or recipient acknowledgment workflow.
3. **`lifecycle_visibility=status_reason_scoped_replacement`**: authorized readers of the original see cancellation status, reason, actor and server time. The replacement-visibility condition is recorded for a possible future separately approved replacement feature; no such feature exists now. Private draft history remains originating-company only.

This supersedes previous cancellation deferral only. Existing five ADR-042 selections, exact-revision stage linkage, independent draft/issue nominations, main-contractor-only write model, immutable issuance, optional explicit-offset overlap and legacy-time rules stay accepted. ADR-041/MTO/MR/PO authorities are not changed.

## User operation

Open an own-company ISSUED detail as a current issuer, read the disclosure warning, enter a required reason and press **Cancel issued notification**. Reason1–4000 characters, not whitespace only. The reason and recorded name/time are visible to all currently authorized original readers, including addressed recipients: do not paste private draft/commercial information. Input is escaped in HTML/PDF. Failed form reason is restored only for the same notice ID, not another detail.

The POST uses `cancellation[version]` (the immutable issued version) and `cancellation[reason]`, with existing authentication/web CSRF protection. Client-supplied actor/company/time/status/grant/body fields are not accepted inside that payload. Successful cancellation redirects to the same detail with the selected language.

Cancellation is terminal, append-only and exactly once **in recorded effect**: one unique event per notice. Repeated/stale/parallel attempts are refused, not reported as another success. No original state/version/number/snapshot/text/recipients/source/date or old private history row is changed; no number is allocated. Another currently nominated same-company issuer can withdraw the notice even if they did not issue it originally. Revoke issue permission and the cancellation action disappears/is refused. A newly nominated main contractor cannot cancel another company's old notice, and a former main contractor without the current grant has no exception.

Current project/company/participation/user-active/quality+document module/standards-pack/discipline grant gates remain; archived/nonwritable projects reject new cancellation. Cancellation can withdraw existing readable issued evidence even when its original ITP revision is now archived, or recipients/source/PO are no longer eligible for a *new issue*. It does not reissue or expand any source access, so it does not revalidate those old references as though issuing new content. Legacy single-time issued notices can be cancelled without inventing activity boundaries. Previously cancelled records remain readable under normal current notice scope after archival/revocation; this does not preserve read access for a departed/unentitled reader.

## Representation and PDF safety

- `inspection_notifications.state` stays **ISSUED** as historical issuance evidence. A separate immutable `inspection_notification_cancellations` event makes the **effective current status CANCELLED**. Integrations must not use raw issued state as proof of a currently active notice; use the cancellation-aware register/detail. No external integration contract or new JSON export was added.
- Register/detail show CANCELLED; unfiltered results retain history. State filter DRAFT is unchanged, **ISSUED now means not cancelled**, and new CANCELLED selects withdrawn notices. Authorized-only counts,25-row pages, search number/current activity reference, source pickers, language/context and overlap remain unchanged. Cancellation reason/actor are not added to search.
- Original readers see an escaped event banner with captured name, reason and UTC time. Names are snapshots, not today's live person name. Snapshot/source/commercial joins are not delegated; recipients do not receive old draft bodies or history counts.
- New PDF downloads retain the issued content/number/version and visibly add the cancellation banner; the status row also says cancelled, not active issued. This is current lifecycle context around retained issue evidence, not a rewritten historical snapshot or new inspection result/certificate.
- PDF rechecks reader scope/entitlement after rendering as before, and now also compares the immutable cancellation event identity. A cancellation committed during rendering refuses stale active bytes with **409**, no PDF disposition/body, and asks for retry. A later retry includes the event. This checks the state at recheck time; it cannot revoke an already downloaded/cached/printed copy or promise no change after the response check. No email/SMS/push/external delivery, signature, legal receipt, attendance, result cancellation or hold/release/proceed is implied.

## Implementation / invariants

Restricting FKs/unique notification link retain history. Insert validates own project/company, writable project, locked ISSUED parent and exact issued version, current actor/membership/entitlement and **latest issue grant**, under the existing project advisory/header lock and notice lock. Actor name, grant UUID, discipline and clock time are captured/overwritten by SQL, not trusted from input. Actor/membership/company/plan/participation rows are held through commit. Duplicate/write/delete and cross-scope attempts are refused. An injected late failure rolls back the event entirely. No parent UPDATE or private-history insert occurs; GET does not create events.

RLS event reads require the same visible issued parent/project; service queries additionally enforce current actor discipline/entitlement/participation. Forced RLS and invoker functions are defense in depth, **not** cryptographic tamper evidence or proof against a privileged DDL operator. Like the existing issuance/history trust model, the application supplies authenticated actor identity to trusted SQL; no new end-user database identity/signature system is claimed. Register uses indexed existence checks plus one page-batched cancellation fetch rather than an N+1 detail fetch. Separate count/page queries are not an atomic concurrent reporting snapshot or performance certification.
