Date: 2026-09-28. User ruling: retain the size range covered by B16.9 through NPS 48; outside that range, users must define data in accordance with the project specification. A limited transcription must never redefine a standard's scope.

## Implemented now

- Standard range explicitly recorded as **NPS 1/2–48**, from B16.9-2018 clause 1.1 (DN 15–1200). `sizeRange` includes the out-of-range policy `PROJECT_SPEC_REQUIRED`.
- Reference pack **v1.2.0** contains **99 rows**: 33 LR90, 33 LR45 and 33 caps, each spanning all tabulated sizes from 1/2 to 48. This does not claim that all fitting families in B16.9 are implemented.
- Added 34 rows against Tables 6.1-1 / 6.1-10 in the supplied PDF; retained every previous dimension value. No geometric interpolation was used.
- Reader exposes `sizeScope()`, independent of the pipe-size catalogue and loaded fitting rows. It recognises numeric/fraction NPS and Persian/Arabic digits without accepting malformed inputs as engineering sizes.
- Both direct lookup and the PMS consumer return `PROJECT_SPEC_REQUIRED` for a positive size outside 1/2–48. They do not label it physically impossible or manufacture B16.9 dimensions, OD or DN.
- A within-range missing pipe-size entry returns `REFERENCE_SIZE_NOT_LOADED`; a missing fitting row returns `REFERENCE_DATA_NOT_LOADED`. These are ingestion/reference coverage gaps, not out-of-standard verdicts.

## Caps 26–48: in range, but applicability is not invented

All twelve E-column values for NPS 26–48 are now retained in the reference pack. The source's missing thickness-threshold and E1 cells are represented by explicit nulls, never zero. `requiresManufacturerAgreement=true` marks the agreement requirement associated with E1 under Table 6.1-10 note (2).

The dimensional reader conservatively returns `CAP_MANUFACTURER_AGREEMENT_REQUIRED` and a null final row for these sizes: it cannot use a missing threshold to select E automatically, and cannot invent an agreed E1. This is an applicability/selection limitation **inside** the standard's range, not exclusion of the sizes. Project-side agreement capture/selection is still to be built. Small-cap threshold selection remains unchanged.

## Outside-range user definitions — standing requirement, UI/storage pending

The range-routing policy is implemented. A project-scoped form/service/storage workflow for users to create these definitions is **not implemented in this increment**. Existing generic component/PMS validation must not be presented as already supporting arbitrary custom sizes end to end.

The next authoring workflow must retain:

- Project/tenant identity; no mutation of universal B16.9 reference packs.
- User-entered nominal size and relevant OD/DN/geometry, with explicit dimension semantics and units. Do not derive a nonstandard OD or dimension from NPS automatically.
- Project Spec identifier, revision and clause/table, source wording, author and review state.
- Distinct project-defined provenance; never label a project-specified value as tabulated B16.9 or silently publish it to other projects.
- Required review/conflict checks; an outside-range definition is neither automatic engineering approval nor a physical impossibility.

Do not let project definitions become a silent fallback for missing rows inside B16.9. Within-range data gaps and manufacturer/purchaser agreements require their own explicit states and provenance.
