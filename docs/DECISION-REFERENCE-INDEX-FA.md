## روش استفاده از مستندات از این پس

پیش از هر تغییر، تصمیم‌های پذیرفته‌شده و اصلاحات تاریخ‌دار مالک بررسی شوند؛ هدف مصوب از محدودیت کد جدا شود و فقط خلأ واقعی به‌عنوان سؤال جدید مطرح شود. تصمیم در سند اصلی اصلاح/تکمیل و این فهرست فقط به آن ارجاع دهد. خلاصهٔ handoff جای تصمیم اصلی را نمی‌گیرد. تاریخچه حفظ و جایگزین‌شدن وضعیت صریح شود؛ در ابهامِ اعتبار یا supersession، تعارض گزارش شود و حدس زده نشود.

## اصلاحات اعمال‌شده

- سؤال‌های تاریخی بخش۸ Requirements حفظ شدند، ولی تعویق اختیار MTO و تصویب قبلی hierarchy pinning مشخص شد.
- چرخهٔ additive/mapping دیگر یک موضوع کاملاً تصمیم‌گیری‌نشده معرفی نمی‌شود؛ قواعد ADR-018 مبنا هستند. target رویدادها، وابستگی اعتبار و اجرای تراکنشیِ admission جدید هنوز طراحی اجرایی‌اند؛ سیاست تازه‌ای خودکار تصویب نشده است.
- محدودیت equality-only header در prototype رفع شد: خود scope یا زنجیرهٔ اجداد صریح در proposal نسخه‌دار بررسی می‌شود. ancestry اثبات‌نشده مسدود می‌ماند و نتیجه حتی در حالت موفق UNADMITTED است. FK فعلی header در برنامه به subsystem اشاره دارد؛ تست مصنوعی parent/project به‌معنای فعال‌شدن این headerها در برنامه نیست.
- تعویق مجوزها توقف همهٔ توسعه نیست: طراحی versioning، احراز شواهد، provenance تغییرناپذیر، بررسی فقط‌خواندنی و تست‌ها بدون نقش جدید قابل ادامه‌اند. writer انسانی admission، permission جدید یا تغییر selector عملیاتی با این اصلاحات مجاز نشده‌اند.

## شواهد

اکنون ۴۶ تست مستقل proposal موفق است: ۳۸ مورد قبلی و ۸ مورد ancestry جدید. selection و planner نیز با ۳۳ و ۲۶ مورد جداگانه دوباره موفق شدند. هیچ کد برنامه، migration، API یا دیتابیس تغییر نکرده و ۴۵۰ هش اجرای کاملِ ۱۱۱۲ تست/۱۶٬۴۸۸ assertion ثابت است. شمار تست‌های مستقل به PHPUnit اضافه نمی‌شود.
