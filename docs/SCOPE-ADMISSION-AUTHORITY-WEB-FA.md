# رابط وب معرفی مستقل عامل‌های admission

**۲۰۲۶-۱۰-۲۴ — پیاده‌سازی و تست متمرکز/متأثر انجام شد؛ مستقر نشده است.**

[نسخهٔ انگلیسی با قرارداد کامل](SCOPE-ADMISSION-AUTHORITY-WEB-EN.md) · [سرویس داخلی](SCOPE-ADMISSION-AUTHORITY-SERVICE-FA.md) · [تصمیم‌های مصوب، بخش پایانی](SCOPE-ADMISSION-AUTHORITY-FA.md)

## وضعیت و مرز ایمنی

صفحهٔ معرفی اقدام، فهرست کاهش سیاست ثبت‌شده برای مالک و تشخیص معرفی‌های خودِ خواننده ساخته شد. محدودیت قبلی «فقط سرویس داخلی/بدون UI» برای **همین برش** رفع شده است، نه برای بسته/بازبینی/شاهد اصیل یا نویسندهٔ admission.

migration، نقش/عامل پیش‌فرض، تغییر منبع، رویداد پذیرش فنی، انتخاب نیاز مؤثر، رزرو، MR/PO/انبار/GRN جدید نداریم. SA-01/02 و DA-01..04 تغییر نکرده‌اند. متن متدهای قبلی configure/key/policy/preflight بایت‌به‌بایت حفظ شده؛ فقط dashboard/suspensionRegister/suspendRecorded/diagnostics افزوده شده‌اند. سرویس/کنترلر خواننده و migrationهای مربوط بدون تغییرند؛ دو قالب خواننده فقط لینک گرفته‌اند. کنترلر، سه قالب و پنج route جدید زیر middleware احراز هویت موجود هستند؛ GETها private/no-store هستند. معرفی مدیریتی حق خواندن/اقدام ارثی نمی‌سازد.

## استفاده از تنظیمات

۱. از تنظیم حق مستقل خواندن، وارد **معرفی مستقل عامل‌های admission** شوید.

۲. شرکت مشارکت‌کنندهٔ واجد شرایط و **یک اقدام مستقل** را انتخاب کنید: پیشنهاد، بازبینی فنی یا ثبت.

۳. منبعی را انتخاب کنید که برای **خود تنظیم‌کننده** قابل رؤیت باشد؛ batch/سند/دامنه/نسخهٔ ساختار دقیق‌اند.

۴. کاربر/نقش شرکتی را صریح انتخاب و دلیل وارد کنید؛ نسخهٔ فعلی همان اقدام نمایش داده می‌شود. پیش‌فرض/wildcard یا معرفی خودکار خواندن/اقدام دیگر نداریم.

۵. پس از ذخیره، همان انتخاب/اقدام باز می‌شود. فقط ۲۰ نسخهٔ آخر **همان اقدام و منبع قابل رؤیت**، شامل UUID سیاست، نسخه، عامل، دلیل و selector ثبت‌شده دیده می‌شوند؛ تاریخچهٔ سیاست خواننده جایگزین آن نمی‌شود.

نامزد می‌تواند قبل از معرفی خواندن تعیین شود؛ اما تا مستقل و جاری مجاز به خواندن نشود، حتی تشخیص/preflight را نمی‌گذراند. مالکِ تنظیم‌کننده بدون معرفی خواندن خودش نیز پاسخ 403 می‌گیرد؛ هشدار کنار لینک این مرز را توضیح می‌دهد.

فهرست فعال خالی/checkbox غایب، selector نامعتبر/شرکت دیگر، اقدام ناشناخته، منبع مخفی/ناموجود و نسخهٔ کهنه رد می‌شوند. تعلیق از فرم معمول نیاز به برداشتن همهٔ انتخاب‌ها دارد؛ برای منبع مخفی از فهرست تعلیق استفاده کنید. فعال‌سازی مجدد به منبع قابل رؤیت و عامل واجد شرایط نیاز دارد. بازنمایی ورودی قدیمی فقط برای همان شرکت/سند/دامنه/ساختار/اقدام است؛ نسخهٔ کهنه و انتخاب خالی حفظ، ورودی بدنوع کنترل و متن تاریخچه escape می‌شود. فرم‌های POST فیلد CSRF دارند؛ این تست‌ها گواهی CSRF تولید/مرورگر نیستند.

## تعلیق سیاست ثبت‌شده، حتی پس از مخفی‌شدن منبع

فهرست فقط آخرین سر هر کلید **شامل اقدام** را نشان می‌دهد: UUID مبهم سیاست و شرکت، اقدام، نسخه، زمان و وضعیت. نه جدول سند/منبع/مشاهده خوانده می‌شود و نه شناسه/نام منبع، مقدار، selector یا دلیل پیشین نمایش داده می‌شود. UUID را از تاریخچهٔ معمولِ منبع قابل رؤیت بشناسید؛ فهرست تعلیق منبع مخفی را برای شما کشف نمی‌کند.

POST فقط `suspension[policy_id,version,reason]` را می‌پذیرد. افزودن selector/فعال‌سازی/اقدام/سند رد می‌شود. سرویس اختیار جاری مالک را بررسی، پروژه را قفل و آرشیو، کلید ناشناخته/مالک یا پروژهٔ دیگر، نسخهٔ قدیمی یا سر ازقبل‌معلق را رد می‌کند؛ سپس جانشین خالی را برای **همان کلید ثبت‌شده** می‌نویسد. منبع/فهرست نامزد خوانده نمی‌شود؛ خروج شرکت هدف هم مانع کاهش نیست.

تکرار/نسخهٔ کهنه رد می‌شود؛ آشکارشدن دوبارهٔ منبع، مجوز قبلی را زنده نمی‌کند. UUID سیاست خواننده جای سیاست اقدام admission پذیرفته نمی‌شود. این endpoint نمی‌تواند مجوز فعال یا گسترده کند. migration/guard قبلی تغییر نکرده‌اند.

## تشخیص فقط معرفی جاری است، نه اجازهٔ تأیید بسته

لینک صفحهٔ منبع انتخاب‌شده یا آمادگی خواننده، به تشخیصِ خود کاربر می‌رود. فقط ارجاع دقیق منبع مصرف می‌شود. ادعاهای شناخته‌شدهٔ `proposer_id`، `reviewer_id` و `action` مرورگر ممنوع‌اند؛ هیچ route وبی preflight اشخاصِ بستهٔ داخلی را فراخوانی نمی‌کند. فیلدهای ناشناخته نمی‌توانند نتیجهٔ منبع/تشخیص معتبرشده را تغییر دهند.

حق خواندن مستقل/جاری با هویت و RLS خود کاربر، ارجاع دقیق، سر سیاست هر اقدام و نقش شرکتیِ تازه بررسی و خواندن در پایان دوباره کنترل می‌شود. معنای «معرفی جاری موجود است» فقط همین است؛ **اجازهٔ تأیید/ثبت این بسته نیست**. بدون معرفی اقدام، هر سه مقدار false است. منبع مخفی/ناموجود UNAVAILABLE و هر سه false است؛ هیچ تاریخچه/metadata سیاست اقدام نمایش داده نمی‌شود. نبود معرفی خواندن، حتی با معرفی اقدام فعال، پاسخ 403 می‌دهد. تعلیق/حذف نقش/لغو خواندن از نسخهٔ قدیمی fallback نمی‌کند.

آرشیو خواندنی می‌ماند اما writable=false است؛ فرم جهش ندارد و POST موفق نمی‌شود. همیشه:

```text
ready_to_admit=false
package_verified=false
operationally_authorized=false
gross=null
```

مقدار نامعلوم است، نه صفر. payload سطر منبع، شاهد، CDE/کتابخانه/موجودی یا مقدار خوانده نمی‌شود. این صفحه تفکیک اشخاص یا تأیید فنی بسته را اثبات نمی‌کند. عامل‌های اصیل ذخیره‌شده، نسخه و اتصال دقیق بازبینی، پوشش تاریخی/توپولوژی، اصالت/نگهداری/اعتبار جاری شاهد و بسته‌شدن وابستگی‌های رؤیت همچنان پیش‌نیاز نویسنده‌اند. preflight قبلی فقط نابرابری شناسه را می‌تواند کنترل کند؛ گواهی بسته/پذیرش نیست. تشخیص مجوز مدت‌دار، snapshot اتمی یا گواهی لغو هم‌زمان عمومی نیست.

## تست و شواهد

**۴۷ تست برنامه / ۲۶۰ assertion موفق، ۱۰۳٫۴۸ ثانیه**: ۱۸ تست HTTP جدید، ۱۷ تست داخلی admission و ۱۲ تست HTTP خواننده. فقط مجموعهٔ متمرکز/متأثر؛ نه کل regression.

پوشش: مهمان/مالک، EN/FA/RTL و private/no-store، فرم/تاریخچهٔ مستقل اقدام، نیاز به خوانندهٔ مستقل/نبود ارث مالک، نبود اقدام پیش‌فرض، رد ادعای اشخاص از مرورگر، منبع مخفی بدون افشای metadata، تعلیق بدون SQL منبع، نسخهٔ کهنه/تکرار/تزریق فعال‌سازی، منع فعال‌سازی مخفی و نبود احیای خودکار، selector شرکت دیگر، UUID از aggregate اشتباه، لغو خواننده/حذف نقش جاری، خروج مشارکت‌کننده، آرشیو، escape تاریخچه/ورودی بدنوع و نبود پرس‌وجوی payload/CDE/انبار یا جهش داده در تشخیص.

اجرای اولیهٔ ۱۵ تست ایراد کپی فیلد مخفی داشت: action اشتباهاً از tuple منبع خوانده می‌شد؛ فهرست به batch_id اصلاح و action جدا بسته شد. اجرای اصلاح‌شدهٔ ۱۵/۱۳۹ و اجرای ناموفق قبلی با ۱۲ موفق، با ۴۷/۲۶۰ نهایی هم‌پوشان و جمع‌نشدنی‌اند. Pint/lint شش PHP، کامپایل/پاک‌کردن Blade، پنج route، نقش معمولی بدون superuser/BYPASSRLS، FORCE RLS/invoker، ثابت‌ماندن کد قبلی، پنج HTML ساختگیِ پاسخ HTTP با CSRF حذف‌شده و زبان صحیح و بررسی لینک/whitespace موفق شدند. فرمان ممیزی استاتیک ابتدا قبل از نوشتن دو گزارش بعدی پوشه را عوض کرده بود؛ آن بررسی‌های مستقل از ریشهٔ repo تکرار شدند، نه تست‌ها.

شواهد: `docs/evidence/2026-10-24-admission-authority-web/`. HTMLها fixture ساختگی HTTP هستند، نه screenshot مرورگر یا دادهٔ تولید. DB خصوصی socket-only با نقش معمولی epcc بعد از بررسی متوقف شد. migration/مجوز/دادهٔ تولید، CI/commit/push، استقرار، گواهی مرورگر یا هم‌زمانی نداشتیم. بسته افزایشی و وابسته به برش‌های قبلی است؛ runtime/vendor/DB داخلش نیست و بسته‌های قبلی بازتولید نشده‌اند.


سخت‌گیری نهایی ورودی، selector به شکل map کلیددار را پیش از رسیدن به CHECK آرایهٔ JSON در DB با HTTP422 رد می‌کند. بعد از این تغییر محدود کنترلر/اعتبارسنجی list، **تمام ۱۸ تست HTTP با ۱۵۲ assertion موفق (۴۱٫۸۹ ثانیه)** در final-http.log ثبت شد. اجرای ۴۷/۲۶۰ متأثر پیش از این سخت‌گیری نهایی بود؛ کد داخلی/HTTP خوانندهٔ بدون تغییر بی‌دلیل تکرار نشد. اجراها هم‌پوشان و جمع‌نشدنی‌اند.

## ادامه و توصیه

قبل از نویسندهٔ پذیرش، بستهٔ پیشنهاد/بازبینیِ اصیل و append-only با هویت canonical نسخه، اتصال مستقل بازبین و مرز رؤیت طراحی و پیاده شود؛ سپس آداپتور واقعی توپولوژی/پوشش تاریخی و اعتبار مستقل شاهد.

**UUID اشخاصِ ادعاشده از مرورگر، هشِ همسان یا شباهت ساختاری را تأیید فنی تلقی نکنید.** بستهٔ ناقص/غیرقابل‌اعتبارسنجی مسدود، مشاهده‌ها UNADMITTED و مقدار ناخالص/باقی‌مانده نامعلوم بمانند. اصلاح/withdrawal تابع چرخهٔ مصوبِ غیرقابل تغییر و بازبینی مستقل است. انتخاب مؤثر و دفتر کامل تعهدات پیش‌نیاز رزرو DA-03 باقی‌اند؛ سیاست عامل‌های مصوب دوباره پرسیده نمی‌شود.
