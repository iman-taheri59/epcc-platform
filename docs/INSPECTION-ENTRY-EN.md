# Inspection recorder configuration and create-only PO observations

2026-10-19 · **IMPLEMENTED / TARGETED VERIFIED** · [فارسی](INSPECTION-ENTRY-FA.md) · [ADR-041](ADR-041-INDEPENDENT-INSPECTION-ENTRY-EN.md)

## Use

1. Owner-company administrator with project.configure opens Project → Procurement → Inspection recorder access. Select eligible active people or company-scoped project roles, enter a reason and save a new version. Initially nobody is nominated; the owner does not inherit recording authority. Suspension creates a new version with no selectors; stale configuration versions are refused. Latest20 versions are displayed and older versions retained.
2. An independently nominated, currently entitled member of TPI/PMC/MC/OWN opens a PO detail through their **existing original read access**. The form appears only with current nomination/membership/discipline, active account, procurement/standards entitlement and writable project. Type alone, MR/PO grant and project configuration are not recording grants. No role is created and no reader is impersonated.
3. Explicitly choose result (PASS/FAIL/CONDITIONAL), stage (WORKS/PRE_SHIPMENT/ON_ARRIVAL), Gregorian inspection date and findings. Neither result nor stage defaults to PASS/acceptance. At least one finding is required for FAIL/CONDITIONAL; PASS may omit findings. Findings are bounded to8000 characters per language. Date is reported data, not a verified timestamp. Fields from failed validation are scalar-safe/escaped and reused only for the same PO UUID.
4. Submit. The server re-resolves the same-project PO under original caller RLS, rechecks authority, locks project/source order and allocates the existing project IRN number. It records the actual recorder company/user, current nomination UUID and server actor-name/time. No user-supplied actor/company/policy/number is accepted.
5. Redirect to PO detail: the new observation, captured recorder name, policy UUID and server time are displayed with existing inspection history; the paginated project inspection register also shows it. Captured identity/time are recorded metadata, not PKI signatures or certification of the inspection/finding/PO version.

The PO buyer stays unchanged; a PMC inspector's record belongs to PMC, not EPC. TPI nomination alone does not unlock a hidden PO; selected original-caller scope intentionally preserves this limitation. EPC/SUB/VEN remain ineligible under the preexisting independence rule even when a nomination is requested. “MC” is management contractor, not mechanical completion.

## Non-effects and limits

A FAIL is still advisory and **does not block physical receipt**. Recording does not change MR/PO state, quantities/prices/source linkage, lots, cached lot inspection verdicts, movements, usable/held/released material, financial decisions or source allocations. It is a PO-linked observation, not a new lot-application/receipt UI. No attachments/evidence verification, legal signature, new distinct-person inspection separation rule, approval of actual observation date, deduplication or commercial fingerprint certification is introduced.

Source PO state is not mutated or restricted to an invented issued-only inspection rule. Current discipline is checked; unknown discipline requires unrestricted current membership. History is not edited: new attributed rows are immutable under the SQL trigger, policy rows have no UPDATE/DELETE policy, and legacy rows cannot be retro-attributed. Existing trusted legacy behavior remains outside a redesigned per-human SQL authority model. Legacy inspection rows remain nullable and untouched; typo correction/supersession/editing requires a separate workflow, not dropping the guard. Repeated deliberate submissions can create separate observations; idempotency is not claimed.

## Implementation

- New POST `procurement.inspection-author-access`: existing owner-company project.configure with current project/module/pack checks, version/reason/selectors/suspension. Directory selection is restricted to active eligible project members and existing company-scoped role memberships, not a global user directory. Individual selectors follow current person/project membership; role selectors additionally bind company.
- New UUID POST `procurement.orders.inspections.create`: strict `inspection[purchase_order_id,result,stage,inspection_date,findings_en,findings_fa]` contract, route-matching source UUID and original-caller RLS. No delegated workspace/SELECT-policy expansion.
- `InspectionAccessService` and `InspectionEntryService`, shared preexisting inspector-type constant, two Blade partials, EN/FA translations, existing register/detail shell. The only functional WarehouseService change exposes its existing inspector-type constant for reuse; legacy receipt behavior stays unchanged.
- Forward-only `2026_10_19_190000_add_independent_inspection_entry.php`: forced-RLS append-only project nomination history plus nullable `entry_policy_id` and `recorded_actor_name` on inspections. No default nominee/data backfill. Original-caller guard validates controlled source/nomination/plan/type and findings, stamps metadata, freezes attributed rows, disallows legacy attribution. No SECURITY DEFINER or buyer context switch.
- New human entry and configuration use `inspection-entry:{projectId}` advisory lock then project row lock. Source PO gets a shared lock. Numbering uses visible project MAX sequence after locking; quality-record RLS already gives participants project inspection visibility. Shared project row locking aligns with legacy Warehouse inspect numbering. Number collisions/overflow and late SQL refusals abort rather than overwrite history. This is not universal raw-SQL concurrency/commit-time revocation certification.

Review preserved prior rules that a generic interpretation of nomination could have bypassed: independent inspecting company type, findings on non-PASS and original IRN numbering. The initial local broad-participant/INSP implementation was corrected before final evidence; not an accepted owner-rule reversal or production incident. See ADR-041 for exact selected authority and deferred delegated-read option.
