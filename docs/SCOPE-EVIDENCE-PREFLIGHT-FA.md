# پیش‌بررسیِ شاهد با هویت اصلی و مرز بستهٔ ترکیبیِ کنترل‌شده

**۲۰۲۶-۱۰-۲۵ — تشخیص داخلی پیاده و تست متمرکز/متأثر شد؛ مستقر نشده است.**

[English contract](SCOPE-EVIDENCE-PREFLIGHT-EN.md) · [نظر متصل به جفت دقیق](SCOPE-STRUCTURE-REVIEWS-FA.md) · [اظهارنامه](SCOPE-STRUCTURE-DECLARATIONS-FA.md) · [کنترل بایت موجود](G01-CDE-EVIDENCE-INTEGRITY-FA.md)

## وضعیت: پیش‌نیاز تحویل شد، نه بستهٔ دائمی

توصیهٔ قبلی، هویت ترکیبیِ غیرقابل‌تغییر برای متن، ساختار و شاهد دقیق بود. بررسی نشان داد کنترل‌کنندهٔ بایت فعلی CDE **دسترسی تضمین‌شده به بایتِ نگهداری‌شده و اعتبار/ابطال جاری شاهد را ثابت نمی‌کند**. ذخیرهٔ نتیجهٔ آن به نام بستهٔ کنترل‌شده این دروازه‌ها را بی‌صدا دور می‌زند. پس این برش فقط پیش‌بررسیِ لازم با هویت اصلی را می‌سازد؛ manifest/هویت ترکیبی و writer اتصال دائمی همچنان بسته‌اند. این تحویل مرحله‌ای است، نه تکمیل writer بسته یا سیاست مهندسی تازه.

اضافه شد: `ScopeEvidencePreflightService`، پیام دوزبانه و۱۶ تست برنامه. **migration، writer دادهٔ دامنه، attachment، UUID/هش بسته، route/UI/خروجی عمومی، نقش/مجوز تازه یا تغییر کد اجرایی قدیمی نداریم.** پیشنهاد، اظهارنامه و نظر قبلی ثابت‌اند؛ SA-01/02 و DA-01..04 دوباره پرسیده یا جایگزین نشده‌اند.

## قرارداد داخلیِ سخت‌گیر

```text
inspect(project, genuine_authenticated_original_User, {
 declaration_id,
 expected_declaration_version, expected_declaration_digest,
 expected_proposal_id, expected_proposal_version, expected_proposal_digest,
 references: {
   topology: { document_id, revision_id, file_id, sha256 },
   coverage: { document_id, revision_id, file_id, sha256 }
 }
})
```

کلید ناشناختهٔ ریشه/تو‌در‌تو، URI/disk/path/actor/state/verification، purpose ناقص و UUID/هش نامعتبر رد می‌شوند. پروژه از رکورد تازهٔ سرور است، نه ورودی شاهد. UUIDها نرمال و هش،۶۴ رقم هگز کوچک است. دو purpose فقط **قالب محدود تشخیص‌اند، نه تصمیم به کفایت دو فایل برای دامنهٔ مهندسی**. یک فایل می‌تواند برای هر دو ادعا شود بدون اثبات هیچ رابطه‌ای.

این facade داخلی از caller مورد اعتماد User واقعیِ احراز‌شده می‌خواهد؛ UUID عامل، احراز هویت نیست. route آینده باید عامل واقعی session را بیاورد؛ endpoint عمومیِ کشف شاهد ایجاد نشده است.

## اجرا و بسته‌بودن مسیر رؤیت

۱. شرکت خود عامل/پروژهٔ دقیق با TenantContext bind و پروژه تازه بارگیری می‌شود؛ اظهارنامه از خوانندهٔ احراز‌شدهٔ ساختار/منبع می‌گذرد. پیشنهاددهنده propose+reader جاری یا عامل واجد شرایط دیگر همان شرکت review+reader جاری، تمام سطرهای مشاهده‌شده و هویت تمام نیاکان را نیاز دارد. record-only/تنظیم‌کننده/پروژه یا شرکت بیگانه/منبع مخفی، دسترسی ارثی نمی‌گیرند.

۲. سر جاری جریان متن و تمام UUID/نسخه/هش‌های مورد انتظار دو محتوا دقیقاً تطابق دارند؛ latest جای ورودی نمی‌نشیند. این تشخیص فقط جفت جاری را می‌پذیرد؛ خواندن پروژهٔ آرشیوی ممکن است، نه نوشتن.

۳. صلاحیت واقعی User، مشارکت شرکت، طرح، عضویت شخصی و نقش جاری دوباره خوانده می‌شوند. **هر دو tuple دقیق CDE پیش از هر فراخوانی Storage** با joinهای invoker/RLS فایل/نسخه/مدرک و پروژه/والد دقیق بررسی می‌شوند. اول فقط discipline واقعی خوانده و `AuthorizationPipeline::check(doc.view, actual_document_discipline)` لازم می‌شود؛ سپس descriptor داخلی خوانده، ثبات discipline کنترل و برای مقایسهٔ پایان نگه داشته می‌شود. tenant به مالک شاهد تغییر نمی‌کند.

۴. entitlement ماژول CDE جدا از procurement و معرفی خواندن منبع است. QC یا SA review، doc.view نمی‌دهد. رشتهٔ خود مدرک شاهد کنترل می‌شود، نه فرضِ رشتهٔ PIPING منبع MTO. WIP خصوصیِ شرکت دیگر مخفی است؛ مدرک منتشرشدهٔ عادیِ قابل‌رؤیت برای مشارکت‌کننده، با RLS فعلی و اختیار مستقل خود عامل خوانده می‌شود. مجوز بین‌شرکتی تازه‌ای ساخته نشده است.

۵. سرویس بایت موجود و بدون تغییر، revision/file/hash دقیق را برای هر purpose می‌سنجد؛ فقط adapter محلیِ canonical و محدود، stream واقعی و اندازه/هش، رد storage نامعتبر/پشتیبانی‌نشده و بررسی دوبارهٔ metadata. URL/S3، کپی فایل، اتصال، current revision جایگزین یا مدرک دیگری با همان هش نداریم.

۶. پس از هر دو stream، صلاحیت CDE و تمام descriptorها تازه خوانده و ساختار/منبع/جفت جاری دوباره بررسی می‌شوند. **تمام** فیلدهای مرتبطِ ابتدا/انتها—رشته، شمارهٔ مدرک، locator/disk/پسوند، هش/اندازه، نسخه/state/suitability/صادرکننده/زمان—مطابق‌اند. تغییر metadata فایل اول هنگام خواندن دوم هم دیده می‌شود. عدم اختیار404 مبهم؛ شکست تمامیت یا drift، BLOCKED با evidence=[] و بدون منشأ جزئی فایل اول است.

۷. فقط موفقیت همهٔ کنترل‌ها، منشأ محدود فعلیِ دو ارجاع، purpose ادعایی/findings و هویت/نسخه/هش والد را برمی‌گرداند؛ نه disk/path، بایت فایل، envelope خام DB یا جزئیات exception. مقدار منبع برنمی‌گردد؛ helper منبع در داخل خودش سطرهای پذیرفته‌شده را می‌خواند/هش می‌کند.

audit معمول pipeline در حالت تراکنش بیرونیِ تحت مالکیت همین متد، پیش از404 نهایی commit می‌شود. تراکنش بیرونی caller هنوز می‌تواند آن را rollback کند؛ رفتار best-effort فعلی به تضمین audit دائمی ارتقا نیافته است. trace تشخیص موفق INSERT/UPDATE/DELETE یا خواندن انبار ندارد؛ audit رد دسترسی استثنای صریحِ نوشتنِ غیردامنه است.

## معنای صادقانهٔ نتیجه

موفقیت: **BYTES_CHECKED_UNRETAINED** و all_evidence_bytes_verified=true؛ هر stream در زمان بررسی با انتظار دقیق مطابق بوده و کنترل‌های metadata/رؤیت مذکور انجام شده‌اند. **نه خواندن اتمیک هم‌زمان، هویت دائمی شاهد، lease نگهداری یا گواهی اعتبار/اختیار**. همیشه:

```text
package_persisted = package_identity_issued = evidence_attached = false
evidence_relationship_verified = evidence_validity_verified = retention_verified = false
package_verified = engineering_approval = ready_to_admit = operationally_authorized = false
admission_state = UNADMITTED; gross = null
```

حتی UUID/هش موقتِ بسته صادر نمی‌شود. BLOCKED منشأ جزئی شاهد یا والد ندارد. وابستگی CDE مخفی/غایب/خارج‌دامنه/بدون entitlement،404 مبهم و شکل/شرط کهنه validation است. WIP ممکن است تشخیص بایت را بگذراند، ولی REVISION_CONTENT_MUTABLE باقی است؛ PUBLISHED/A1 یا ARCHIVED به مناسب/جاری/مجاز بودن برای purpose تعبیر نمی‌شود. نسخهٔ آرشیوی دقیق با نسخهٔ تازه عوض نمی‌شود.

نظر قبلی فقط به محتوای خودش وصل می‌ماند؛ پیش‌بررسی آن را بازبینی شاهد نمی‌نامد، هش/پرچم تأییدش را عوض نمی‌کند و evidence_attached=false اظهارنامه ثابت است. UI و پرچم‌های آمادگی قبلی تغییر نکرده‌اند.

## محدودیت‌ها و نقصِ مشاهده‌شده در مسیر قدیمی

- مقایسهٔ descriptor بهترین بررسی موجود است؛ نه اتمیک DB/فایل‌سیستم، کشف تمام ABAها، تضمین علیه تغییر بعدی بایت یا commit پنهان در isolation caller. اثبات دو worker هم‌زمان، بازیابی crash، قفل نگهداری یا performance نداریم. هر یک از دو stream تا سقف۱۰۰MiB موجود است؛ adapter دوردست/سقف تازه نداریم.
- تست لغو/drift میان stream با callback آزمایشی DB را تغییر می‌دهد؛ **اثبات رقابت worker مستقل نیست**. نشان می‌دهد کنترل نهاییِ عامل اصلی و تطابق کل descriptor، خروجی جزئی را کنار می‌گذارد.
- مدیر storage/فایل‌سیستم/DB همچنان مورد اعتمادند؛ SHA نه امضای صادرکننده است نه اختیار تاریخی مهندسی. هویت ساختاری منجمد/پوشش سطرهای فعلی، دامنهٔ مهندسیِ کامل و معتبر تاریخی را ثابت نمی‌کند.
- تشخیص سر نسخه بر کامل‌بودن policy metadata همان شرکت/پروژه متکی است؛ inventory وابستگی پنهان نیست. فقط دو tuple ورودی بررسی می‌شوند، نه تمام شاهد فنی یا تعهدات.
- **توصیهٔ اصلاحی:** `DocumentController::authorize()` فعلی، از جمله در دانلود، `check(user, capability, project)` را بدون context رشته فراخوانی می‌کند. facade جدید رشتهٔ واقعی شاهد را صریح می‌دهد؛ نباید ادعا کرد مسیر قدیمی همین کنترل شخصی را دارد. رفتار index/review/download و تست‌های RLS/عضویت در اصلاح محدود و جداگانه ممیزی شوند، پیش از ادعای پوشش سراسری رشته. controller قدیمی، ماتریس رؤیت یا مجوز افراد در این برش بی‌صدا تغییر نکرده‌اند.
- خواندنِ مستقل عامل record-only، adapter تاریخی معتبر/disposition، بستهٔ دائمی، نگهداری/اعتبار جاری، تأیید مستقل مثبت، ثبت با grant جدا/چرخهٔ admission/انتخاب مؤثر و رزرو اتمیک DA-03 با دفتر کامل همچنان غایب/بسته‌اند. اختیار خرید/QA/CDE/پذیرش MTO استنتاج نمی‌شود.

## قرارداد پیشنهادیِ ترکیب آینده — پیاده یا مجوز تازهٔ مصوب نیست

هویت ترکیبی آینده باید ID/نسخه/هش خودش، متن و ساختار دقیق **و** ID/نسخه/هش manifest غیرقابل‌تغییر را متصل کند. هر ورودی باید revision/file کنترل‌شده و بایت واقعی، رابطهٔ purpose با ارزیابی صریح، proof/handle نگهداری و وضعیت قابل‌رؤیت اعتبار/ابطال جاری داشته باشد. این‌ها پیشنهاد فنی‌اند، نه رکورد موجود یا انتصاب اختیار.

- پیش از رؤیت تمام وابستگی‌های واقعی با عامل اصلی و احراز دسترسی به بایت نگهداری‌شده/اعتبار جاری، manifest کنترل‌شده ساخته نشود. URL/هش/عنوان/انتشار یا lookup خالیِ ابطال جایگزین نیست. مدت نگهداری/اختیار operator از SA-01 یا معرفی receipt/QA اختراع نمی‌شود.
- اضافه/تغییر شاهد، نسخهٔ ترکیبی تازه می‌خواهد. جفت والدِ ثابت می‌تواند بدون جهش خودش به هویت ترکیبی جدید ارجاع داده شود؛ نظرهای قبلیِ متن/جفت خودکار آن را پوشش نمی‌دهند. بازبینی مستقل آینده باید ترکیب کامل و وابستگی‌های تازه را بررسی کند؛ migration «نظر قدیمی را approved کن» ممنوع است.
- ثبت پذیرش، تفکیک اشخاص و grant مستقل جاری ثبت را روی ترکیب کاملِ دقیق و مستقلاً تأییدشده، به‌همراه دروازه‌های منبع/اعتبار/چرخه نیاز دارد. اختیار پیشنهاد این‌ها را حذف نمی‌کند؛ تشخیص حاضر snapshot/gواهی نگهداری برای writer مثبت نیست.
- بسته‌بودن inventory وابستگی/اعتبار زیر policy واقعی آینده اثبات شود؛ رکورد مخفی/فهرست محدود دلیل نبودن نیست. تا وجود این کنترل‌ها، writer بسته/پذیرش/رزرو بسته می‌ماند. سیاست مصوب ثابت؛ هر عمل جدیدِ privileged نگهداری طراحی اختیار صریح خودش را لازم دارد، نه معرفی پیش‌فرض.

## اعتبارسنجی و تحویل

- نهایی متمرکز: **۱۶ تست/۸۵ assertion موفق،۴۱٫۷۳ ثانیه**؛ مرجع سرویس جدید.۱۲/۷۱ اولیه در۳۲٫۷۰ ثانیه هم‌پوشان است.
- اجرای متأثر:۵۳ موفق/۲۶۴ assertion و **یک خطای fixture تست** به‌علت نام کلاس Plan بدون qualification پس از افزودن تست؛ نه خطای منطق تولید. دو کلاس همراهِ بدون تغییر،۲۲ CDE integrity و۱۶ اظهارنامه=۳۸ تست، موفق بودند. فقط نام Plan در تست اصلاح و تمام۱۶ تست جدید موفق شد؛۳۸ تست بی‌تغییر بی‌دلیل تکرار نشد. این اجراها هم‌پوشان‌اند؛ **اجرای یک‌بارهٔ۵۴ تستِ پاک یا کل regression نیستند**. log خطای اولیه حفظ شده است.
- پوشش: جفت دقیق، استقلال RBAC/entitlement/رشتهٔ واقعی CDE، actor با دادهٔ cacheشده، احراز هر دو وابستگی پیش از Storage، والد مخفی/شاهد خصوصی شرکت دیگر و انتشار عادی، شکل سخت‌گیر/تزریق، تمام شروط کهنه/سر نسخه، هش/اندازه/فایل مخفی یا خراب بدون افشای جزئی، یک فایل برای دو purpose بدون اثبات، نسخه/پروژه آرشیوی، عدم writer/جهش منبع/ارتقای نظر قبلی، لغو و drift locator فایل اول میان stream و رفتار audit.
- Disk fake، scratch/stream و هش واقعی محلی است؛ فقط تزریق لغو/drift callback کنترل‌شده دارد. policyهای مخفی‌سازی با finally حذف شدند؛ audit نهایی نبود fixture اضافی/trigger خاموش را تأیید کرد.
- Pint/lint چهار PHP، whitespace، نقش معمولی epcc بدون SUPERUSER/BYPASSRLS/CREATEDB، FORCE RLS/guard موجود و ثبات بایت کد قبلی بررسی شد. HTTP/مرورگر/HTML تازه، کل regression/CI، migration/داده/مجوز مشتری، استقرار/commit/push نداشتیم. DB خصوصی socket-only بعداً متوقف شد.
