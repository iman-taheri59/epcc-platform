## Selection and behavior

User selected `next_prerequisite_increment=company_picker`: replace manual UUID entry with readable name/code selection **only from prerequisites the current user may already read**. No general project/company directory, extra source access, new role or write authority. ADR-045 company management/report/review/disclosure, retained issue/PDF, inherited-stage and archive/cancel boundaries remain.

The existing GET register now has a company name/code search and native select. No JavaScript or extra endpoint is required. Search is optional literal case-insensitive substring over recorded code, English name or Persian name; max100 characters. `%`, `_`, `!` and quotes are data. Apply to search the options, select a company, then apply. Search alone does **not** filter prerequisite rows or their totals; the selected company UUID does. Choose All visible declaring companies to clear selection. Clear filters resets all filters/search and both page positions.

Options come from all current visible prerequisite records, **before** register status/notice/company filters. Thus a zero-row status/notice result does not erase the company choices. Mere project participation, live company existence, being a selected recipient with no prerequisite, or being the last reporter does not make an option. One option per stable **declaring** company UUID, not per note/actor. For its label, take the latest-created visible prerequisite's captured company code/bilingual name (created_at descending, UUID ascending tie-break). This is a recorded declaration-time name, **not today's company directory name**, latest report actor company, legal certification or proof of current contractual identity. Later follow-up updates cannot replace declaring-company metadata. Historical alternate labels are not searched as aliases; only the representative label is searched.

Company options are25/page (`prerequisite_company_page`), ordered recorded code then company UUID. Search narrows option pages; matched option total is authorized-scope-only. Register records retain their independent25/page `prerequisite_register_page`. Browsing either set preserves the other's current page, language and normalized filters; applying the GET form or row company/notice shortcuts resets both. Language switching preserves both. Unrelated query keys are not propagated. This remains live offset pagination, not a frozen dataset.

A currently selected visible company is pinned to the select even outside the current search/page (up to25 listed options +one pinned selection +All). Search-match count excludes that pinned extra option. This prevents silently losing a valid filter. A well-formed but no-longer-visible/unknown selected UUID is retained with a **generic unavailable** label and scoped zero records; no foreign name lookup or silent reset to All. Existing bookmark/row-link `prerequisite_company` UUID API is unchanged; manual UUID entry is no longer needed in the primary UI.
