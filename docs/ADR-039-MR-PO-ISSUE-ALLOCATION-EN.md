# ADR-039 — full-copy MR source allocation at PO issuance

2026-10-19. Implements accepted ADR-038 `full_copy_issue_allocation`, retaining original-drafter pricing and ADR-036 independent target-buyer finance/issuer nominations and three actual people. No new authority decision is needed.

Allocation records issued commitments, not stock receipt, MR mutation or financial reservation. Full-copy drafts and financial approvals remain non-reserving and may coexist. At issuance, active lines each map to their real approved MR-line ID; exact cumulative allocation must not exceed the current approved quantity. No partial purchase, cancellation release or synthetic negative allocation is exposed. A full-copy issue consumes the available commitment capacity; further full-copy issues are refused.

The existing version-bound journal is extended with an opaque source hash generated by the database from the current MR header/line records. Financial/issue decisions retain that hash without delegating general MR contents to counterparties. Issue requires both exact PO content and the same still-current source version as the latest financial decision. Existing manual PO canonical hashes and historical decisions remain unchanged.

MR eligibility requires a currently approved, same-buyer/project/category full-copy match and a current complete controlled-pricing revision for the exact PO version. Unknown non-draft/historically issued legacy commitments, including source-linked lines without a header link, block execution pending reconciliation; they are never backfilled or assumed zero. This increment has no legacy reconciliation write endpoint.

A forced-RLS append-only `po_mr_allocations` ledger stores project/buyer, actual PO and MR header/line identities, issue decision, exact quantity, approved quantity/unit, source hash and issue timestamp. The decision guard takes the project PO-entry lock, PO/source header and source-line locks; allocation guards enforce identity and exact quantity ceiling. An AFTER INSERT issue trigger creates all allocations; deferred constraints require full allocation coverage and the applied ISSUED transition. Allocation/decision/transition failure rolls back the transaction. Existing issued commercial freeze and unchanged forecast/receipt behavior remain.

The dedicated buyer-scoped, category-separated execution workspace exposes only that PO's commercial data, opaque source version and own allocation evidence. Generic detail/MR/warehouse RLS and MTO deferrals stay unchanged. Source data may evolve later through existing trusted workflows; historical allocations are retained and do not auto-release, rewrite signatures or change the MR to ORDERED. Real multi-connection lock-order/revocation tests remain release gates, not claimed by single-connection targeted tests.

Implemented / targeted-verified: 108 related tests/746 assertions PASS, including one actual two-PDO-connection issue contention scenario; [delivery guide and remaining gates](PO-MR-ISSUE-ALLOCATION-EN.md).


Deferred-check correction: rebind only the immutable event buyer/project during validation and restore the caller scope; this fixes cross-company issuer commits without SECURITY DEFINER or generic read delegation. Legacy header/line issuance cannot bypass source capacity once enrolled in the controlled ledger.
