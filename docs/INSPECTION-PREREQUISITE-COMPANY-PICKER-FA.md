## انتخاب و رفتار

کاربر `next_prerequisite_increment=company_picker` را برگزید: انتخاب با نام/کد به‌جای ورود دستی UUID، **فقط از پیش‌نیازهای قابل‌رؤیت فعلی کاربر**. نه directory عمومی شرکت/پروژه، دسترسی منبع، نقش یا اختیار نوشتن تازه. مدیریت/گزارش/بررسی/دید ADR-045، اصل/PDF محفوظ، مرحلهٔ موروثی و مرز ابطال/بایگانی ثابت‌اند.

GET فهرست اکنون جست‌وجوی نام/کد و select بومی دارد؛ بدون JavaScript یا endpoint تازه. جست‌وجو اختیاری، زیررشته‌ای و غیرحساس به بزرگی حروف در کد/نام فارسی/انگلیسی ثبت‌شده، حداکثر۱۰۰ نویسه؛ `%`، `_`، `!` و quote داده‌اند. برای جست‌وجوی گزینه‌ها اعمال، سپس شرکت را انتخاب و اعمال کنید. جست‌وجو به‌تنهایی **ردیف‌ها یا total پیش‌نیاز** را فیلتر نمی‌کند؛ UUID شرکت انتخاب‌شده فیلتر می‌کند. «همهٔ شرکت‌های اعلام‌کنندهٔ قابل‌رؤیت» انتخاب را پاک می‌کند؛ پاک‌کردن فیلترها همهٔ شروط/جست‌وجو و هر دو صفحه را بازنشانی می‌کند.

گزینه‌ها از همهٔ پیش‌نیازهای قابل‌رؤیت فعلی **پیش از فیلتر وضعیت/اعلان/شرکت نتایج** می‌آیند؛ نتیجهٔ صفر، گزینه‌ها را از بین نمی‌برد. صرف مشارکت پروژه، وجود شرکت زنده، گیرنده‌بودن بدون پیش‌نیاز یا آخرین گزارشگر بودن، گزینه نمی‌سازد. یک گزینه به‌ازای UUID ثابت شرکت **اعلام‌کننده**، نه هر شخص/یادداشت. برچسب از کد/نام دو‌زبانهٔ snapshot آخرین پیش‌نیاز قابل‌رؤیتِ ایجادشدهٔ همان شرکت می‌آید (created_at نزولی، UUID صعودی برای رفع تساوی). این نام ثبت‌شده هنگام اعلام است؛ **نه نام زندهٔ directory**، شرکت آخرین گزارشگر، هویت قراردادی فعلی یا گواهی حقوقی. پیگیری بعدی metadata اعلام‌کننده را عوض نمی‌کند. نام‌های قدیمیِ دیگر alias جست‌وجو نیستند؛ فقط همین برچسب نماینده جست‌وجو می‌شود.

گزینه‌ها۲۵تایی با `prerequisite_company_page`، به‌ترتیب کد ثبت‌شده و UUID؛ جست‌وجو صفحه‌های گزینه را محدود و تعداد فقط گزینه‌های مجاز مطابق را می‌شمارد. ردیف‌های فهرست صفحهٔ مستقل۲۵تایی `prerequisite_register_page` دارند. مرور هرکدام صفحهٔ جاری دیگری، زبان و شروط نرمال را حفظ؛ اعمال فرم GET یا میانبر شرکت/اعلان هر دو صفحه را بازنشانی می‌کند. تغییر زبان هر دو صفحه را حفظ؛ query نامرتبط منتشر نمی‌شود. صفحه‌بندی جاری است، نه dataset ثابت.

شرکت انتخاب‌شدهٔ قابل‌رؤیت حتی خارج از صفحه/جست‌وجو در select حفظ می‌شود: حداکثر۲۵ گزینهٔ صفحه +یک انتخاب حفظ‌شده +همه. تعداد مطابق جست‌وجو، انتخاب اضافهٔ حفظ‌شده را نمی‌شمارد. این مانع از دست‌رفتن پنهانی فیلتر است. UUID معتبر اما نامعلوم/دیگر غیرقابل‌رؤیت با برچسب **عمومیِ در دسترس نیست** و نتیجهٔ صفر محدود حفظ می‌شود؛ نه lookup نام خارجی یا بازنشانی به همه. API فعلی `prerequisite_company` در bookmark/پیوند ردیف ثابت است؛ ورود دستی UUID در رابط اصلی لازم نیست.

## دسترسی و تمامیت

migration/جدول/index/RLS/نقش/مجوز/POST/PDF تغییر نکرده است. سرویس clone همان join اصل/پیش‌نیاز با پروژه/نسخهٔ صدور/رشته/ISSUED و رشتهٔ خواننده را پیش از فیلتر نتایج به‌کار می‌برد؛ هر دو FORCE RLS محفوظ‌اند. DISTINCT ON در PostgreSQL یک نمایندهٔ ثبت‌شدهٔ مجاز برای هر شرکت، سپس subquery صفحه‌بندی محدود می‌سازد؛ resolve انتخاب هم از همان scope است. directory زندهٔ شرکت/شخص خارجی، منبع ITP/نسخه، تاریخچهٔ خصوصی یا رویداد پیش‌نیاز برای برچسب‌ها خوانده نمی‌شود. read موجود هویت فعال/عضویت/مشارکت/کیفیت/pack را دوباره بررسی؛ انتخاب شرکت دسترسی اعلان تازه نمی‌دهد.

`prerequisite_company_q` چهارمین کلید اختیاری نرمال GET است، نه فیلد نوشتن. آرایه، متن بلند، UTF-8 نامعتبر و NUL با۴۲۲ رد؛ query اصلی و رد زودهنگام NUL فهرست محفوظ. متن/optionها escape، زبان از snapshot؛ cache خصوصی/no-store ثابت. سوابق باطل/بایگانی همچنان می‌توانند گزینهٔ قابل‌رؤیت بدهند و فقط‌خواندنی‌اند؛ ابطال اصل به‌تنهایی نام شرکت را حذف نمی‌کند. زوال صلاحیت خواننده همان دسترسی/گزینه‌های جاری را حذف می‌کند.

## بازیابی سورس و بررسی دقیق

بخشی از کد فهرست در workspace فعلی باقی نبود، ولی آرشیو کنترل‌شده موجود بود.۱۶ فایل سورس از آرشیو قبلی بازیابی؛ پیش از آن فایل‌های متفاوت موجود در `pre-recovery-source.tar.gz` حفظ شدند و سورسی دور ریخته نشد. hash آرشیو/مسیرهای بازیابی در شواهد و آرشیو جدید جدا است. این بازیابی محدود وابستگی‌های قابلیت است، نه گواه بازسازی تمام مخزن. روی کار جدید کورکورانه restore نشود؛ manifest مقایسه و تفاوت نگه‌داری شود.

[شواهد](evidence/2026-10-20-prerequisite-company-picker/README.md): **۵۶ آزمون/۱۷۹۳ assertion موفق** در۴۳٫۳۴ثانیه، بدون skip؛۸ feature جدید انتخابگر،۴ unit فیلتر (یکی تازه)،۱۴ feature مرتبط فهرست/بازیابی و۳۰ مورد خالص مرحله. پوشش گزینه‌های فقط قابل‌رؤیت/اعلان پنهان/غیرگیرنده، حذف تکرار و نام ثبت‌شده در برابر directory زنده/گزارشگر، جست‌وجوی عین متن دو‌زبانه و استقلال نتایج، انتخاب ناموجود، نوع/NUL، رشته/پروژهٔ جاری، بایگانی/ابطال، escape/عدم تغییر با GET و fixture واقعی۲۷شرکت با هر دو صفحهٔ دوم و انتخاب خارج صفحه. نه full regression/CI/مرورگر/بار/تولید؛ شمارش‌های قبلی تاریخی و غیرقابل‌جمع‌اند.

اجراهای میانی حفظ شدند: helper آزمون `options()` با helper HTTP چارچوب تداخل داشت و نامش اصلاح شد؛ fixture تغییر عضویت پس از بایگانی به‌درستی با RLS رد شد، سپس reopen با مدل حافظه‌ای قدیمی خطا داد. fixture از مسیر موجود مالک و با project تازه بازگشایی و بعد عضویت اصلاح شد؛ سیاست بایگانی ضعیف نشد.۵۶ نهایی موفق؛ شکست‌های قبلی سبز معرفی نمی‌شوند. وابستگی PHP از lock موجود بازسازی؛ PostgreSQL17 خصوصی فقط socket و نقش بدون superuser/bypassRLS؛ DB پس از بررسی خاموش. بدون commit/push/استقرار.

Pint/lint/Blade/لینک، hash، audit DB و bundle سورس بدون credential ثبت شد. HTML مصنوعی دو‌زبانه شاهد رندر view است، نه تأیید تعاملی مرورگر. migration قدیمی یا مجموعهٔ گستردهٔ گردش/PDF برای این انتخابگر فقط‌خواندنی تکرار نشد.

## باقی‌مانده / پیشنهاد

فقط پیشنهاد انتخابگر خوانا بسته شد. فیلتر فقط اصل فعال، PDF/خروجی، یادآور، آمادگی/hold فنی و آیتم ساختاریافته همچنان گام‌های جدا/تصویب‌نشده‌اند. جست‌وجوی aliasهای قدیمی یا هویت قراردادی زنده، معنای صریح می‌خواهد؛ directory گسترده‌تر پنهانی خوانده نشود. بررسی index/بار با حجم واقعی انجام شود؛ صفحه‌بندی به‌معنای زمان ثابت تمام countها نیست.

### اصلاح ماندگاری runtime

REBUILD.md بخش۰ از قبل vendor در cache مستثنا را الزام کرده است. app/vendor واقعی با۱۶۷۸۰ فایل وابستگی موجود بود؛ بیش از سقف تقریبی۱۰۰۰۰ فایل snapshot پیش از سورس پروژه. چیدمان با symlink به `/home/user/.cache/prerequisite-picker-vendor` اصلاح و مسیر autoload با `COMPOSER_VENDOR_DIR=/home/user/.cache/prerequisite-picker-vendor composer dump-autoload --no-scripts` بازتولید شد. صرف انتقال اولیه مسیرهای نسبی قدیمی را نامعتبر کرد؛ بازتولید اصلاح کرد.۳۴ مورد خالص/فیلتر با۶۷ assertion در۰٫۲۸ثانیه موفق و هم‌پوشان با۵۶ نهایی است. cache ماندگار نیست؛ پس از reset با vendor-dir صریح/راهنمای REBUILD وابستگی بازسازی شود، نه vendor واقعیِ ماندگار. آرشیو سورس پشتیبان مستقل بازیابی است؛ این اصلاح ریسک معتبر truncation را می‌بندد، نه اثبات علت هر فایل مفقود.
