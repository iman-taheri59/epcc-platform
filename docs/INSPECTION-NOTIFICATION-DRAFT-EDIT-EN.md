## Accepted scope and entry

The user explicitly selected **draft editing only** (`draft_only`), reusing the existing independent main-contractor draft permission, current company and optimistic version checks. Cancellation/replacement and rescheduling of issued notices were not approved. Implementation keeps the ITP revision/stage fixed: an eligible reader of an own-company DRAFT opens its detail → **Edit draft**. Change activity reference, planned activity start/end with explicit offsets, location, explicit recipients, optional PO reference, English/Persian notes. Source revision/stage, discipline, company/project, original creator/time and original entry permission evidence cannot be changed. To use another source, create a separate draft; no silent deletion or cancellation is provided.

## Authorization and persistence

- Same independent `draft` grant, not issue-only, result recording, procurement or a new role. Any currently explicitly granted main-contractor project member may edit that company's draft; it is **not** an original-author-only pricing rule. Original creator remains; last editor is separately attributed. Recipient/configuration administrator alone cannot edit. Main-contractor change or revoked grant prevents save.
- Current active actor, project participation, quality/pack entitlement, discipline scope, original-caller doc.view and writable project are checked. Current ITP visibility/non-archival, valid project recipients and originally visible same-project/same-discipline optional PO are revalidated on save. No source-read delegation or stock/MTO/MR/PO/inspection-result mutation.
- `GET .../{notificationId}/edit` is read-only; `PUT .../{notificationId}` validates a strict `notification` payload, fixed source and explicit `version`. The existing project advisory gate and project FOR NO KEY UPDATE plus draft row lock serialize writes. Exactly matching current version is mandatory. Each successful save increments it once; no notification sequence/number, issue time or issued snapshot is allocated. Even identical submitted content is an explicit successful save and advances version.
- Stale saves return422 instead of overwriting; JSON callers receive validation errors. HTML validation returns to the form. Old input is recovered only for the exact notice UUID and same current version; stale or other-notice form state is not silently rebased. Reopen/review current data before resubmitting. Invalid nested input is not rendered as text or HTML.
- Issuance uses the **latest draft version**, then advances it once: two edits produce DRAFT v3, issue produces ISSUED v4. Existing unedited issued v2 remains valid. An already displayed issue form at an old version is refused. Issued content/evidence and last-edit metadata remain immutable, and existing PDF readers/export still work after edited issuance.
- New nullable columns retain **last** editor UUID, editing-settings UUID and database-recorded edit time. Detail shows latest editor UUID/time. Original creator/time/entry-setting stay fixed. These summary columns alone are not full history. A separate append-only journal now retains every future successful edit’s before/after/editor; pre-install changes are not reconstructed (see current history guide). Do not claim a complete revision audit trail or electronic signature.

The original migration is untouched. SQL permits only the explicit draft mutable fields, version+1 and latest-edit evidence; it rechecks current draft permission/source/recipients. Source/creation rewrites, version jumps, issued edits/deletes and issuance changing content remain refused. Existing forced RLS and policies are unchanged. Test-only populated forward-upgrade reconstruction verifies old DRAFT v1 and ISSUED v2 on an archived project are preserved; no backfill of historical body/snapshot or default permission.

Deploy the forward migration with the matching application version using the project's normal backup/release procedure. Do **not** roll back by discarding edited versions: down() deliberately refuses. No production migration or deployment was run.
